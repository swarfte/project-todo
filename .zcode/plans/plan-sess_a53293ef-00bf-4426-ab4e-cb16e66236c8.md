## 目標
為 Windows / macOS 版本實作「記住視窗關閉前的大小與位置,下次開啟時還原到相同的位置與大小」。沿用專案既有架構(純 Dart 層,使用者已選定):

- `window_manager` 套件(桌面專用)→ 透過 **conditional export** 抽象化,web/Android 為 no-op stub
- 持久化統一走 `ConfigService`(SharedPreferences,含 `dev_`/release 前綴)
- 啟動點在 `main.dart`(`WidgetsFlutterBinding.ensureInitialized()` → `await windowPin.ensureInitialized()`)

## 需要持久化的狀態
在 `ConfigService` 增加 keys(並加入 `_ownedKeys` 讓 `clearConfig()` 一併清除):
- `window_x`, `window_y`, `window_w`, `window_h`(doubles)→ **normal(非最大化、非全螢幕)** 狀態下的視窗外框
- `window_maximized`(bool)
- `window_fullscreen`(bool)

> 為什麼要分開存「normal bounds」:視窗最大化時 `getBounds()` 回傳的是最大化後的全螢幕外框,不是還原大小。因此最大化時只記錄 `maximized=true` 並保留舊的 normal bounds;只有在 normal 狀態移動/縮放時才更新 normal bounds,這樣還原後「取消最大化」才會回到正確大小。

## 新增檔案(沿用 `window_pin` 的 conditional-export 模式)

1. **`lib/core/platform/window_geometry.dart`** — barrel,`export 'window_geometry_stub.dart' if (dart.library.io) 'window_geometry_io.dart';`
2. **`lib/core/platform/window_geometry_io.dart`** — `WindowGeometry` 類,純 `window_manager` 封裝:
   - `bool get isSupported` → `Platform.isWindows || Platform.isMacOS || Platform.isLinux`
   - `Future<void> ensureInitialized()` → `windowManager.ensureInitialized()`(idempotent)
   - `Future<Rect> getBounds()`
   - `Future<void> setBounds(Rect bounds)`
   - `Future<bool> isMaximized()` / `Future<bool> isFullScreen()`
   - `Future<void> maximize()` / `Future<void> setFullScreen(bool)`
   - `void startTracking(void Function() onGeometryChanged)` → 註冊一個內部 `WindowListener`,把 `onWindowMoved/onWindowResized/onWindowMaximize/onWindowUnmaximize/onWindowEnterFullScreen/onWindowLeaveFullScreen` 都轉呼叫 `onGeometryChanged`
   - `void stopTracking()`
   - 每個方法皆以 `if (!isSupported) return;` 守護(跟 `window_pin_io` 一致),所以 Android/IO 也不會誤觸
3. **`lib/core/platform/window_geometry_stub.dart`** — 同介面的 no-op,`isSupported=false`(web 用)

## 修改檔案

4. **`lib/core/storage/preferences.dart`** — 新增 getter/setter:
   - `saveWindowBounds(Rect)` / `Rect? getWindowBounds()`(任一值缺失回傳 null)
   - `saveWindowMaximized(bool)` / `bool getWindowMaximized()`
   - `saveWindowFullScreen(bool)` / `bool getWindowFullScreen()`
   - 對應 keys 加入 `_ownedKeys`

5. **`lib/core/state/app_providers.dart`** — 新增(沿用此檔放視窗相關 Riverpod 狀態的慣例):
   - `final WindowGeometry windowGeometry = const WindowGeometry();`(對照 `windowPin`)
   - `WindowGeometryController`(Notifier/或單純類別):
     - `Future<void> restore()` → 讀 ConfigService,若有合理 normal bounds 則 `setBounds`(含基本合理性檢查:size > 最小值、position 不至於極端負值),再依 `maximized`/`fullscreen` 旗標呼叫 `maximize()`/`setFullScreen(true)`
     - `void startTracking()` → 向 `windowGeometry` 註冊回呼;回呼內:
       - 查詢 `isMaximized()` / `isFullScreen()`
       - 若皆為 false → 讀 `getBounds()` 並以 **節流(~400ms)** 寫入 normal bounds keys
       - 旗標變化時立即寫入(便宜)
     - `void _flush()` → 關閉前 best-effort 立即寫入最後狀態
     - 處理 `windowGeometry.startTracking` 回呼中只負責更新 normal bounds(最大化/全螢幕中不覆寫)
   - 用 `configServiceProvider` 取得 `ConfigService`,錯誤透過 `Logger('project_todo.window')` 記錄

6. **`lib/main.dart`** — 在 `await windowPin.ensureInitialized();` 之後:
   - `final geometry = container.read(windowGeometryControllerProvider);`(或直接 new)
   - `await windowGeometry.ensureInitialized();`(idempotent)
   - `await geometry.restore();`(僅 `windowGeometry.isSupported` 時)
   - `geometry.startTracking();`
   - 註解說明僅在桌面有意義、其餘平台為 no-op

## 設計取捨(已決定)
- **擷取策略**:持續節流寫入(移動/縮放/旗標變化)+ 關閉時 best-effort flush,**不使用 `setPreventClose`**。理由:節流寫入已讓狀態隨時新鮮(誤差 <400ms);避免改動關閉生命週期,降低風險。最多只會丟失最後一個節流視窗的位移,對 todo app 完全可接受。
- **多顯示器/離螢幕**:window_manager 0.5.2 無 display 列舉 API,故只做基本 sanity clamp(size 正向、position 不極端)。完整跨螢幕邊界 clamp 為已知限制,會在程式碼註解標明。
- **不修改 native runner**(Windows `win32_window.cpp` / macOS `MainFlutterWindow.swift`):使用者已選純 Dart 還原。冷啟動可能有極輕微(約 1 畫格)閃爍。
